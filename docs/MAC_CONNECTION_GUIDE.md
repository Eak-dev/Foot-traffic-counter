# คู่มือ Mac: กรอก IP กล้องในเครื่องและตรวจสถานะ (OD-25)

> สิทธิ์และขอบเขต: [PROJECT_CONTROL.md](../PROJECT_CONTROL.md) · เครื่องมือ: [`tools/ft_connect.py`](../tools/ft_connect.py)
> เอกสารนี้เป็นคู่มือใช้เครื่องมือในเครื่องเท่านั้น **ไม่ใช่การเปิดเกตเชื่อมต่อกล้องจริง**

## วิธีใช้งานหลักปัจจุบัน: Owner ใช้ iPhone (OD-26)

**OD-34/35 ผลล่าสุด:** OS route ของ Mac บ้านไป IP ที่บันทึกไว้ผ่าน LAN บ้าน เพราะ subnet ทับกัน; ไม่ผ่าน tunnel ร้าน. Owner สั่งแก้จากบ้านตาม [HOME_CONNECTION_PLAN](HOME_CONNECTION_PLAN.md); ไม่ย้าย Mac เป็นขั้นบังคับ. ตอนนี้ต้องเข้าหน้า router ร้านผ่าน iPhone เพื่อดู capability จริง แล้ว PO เลือกและตั้ง client/route ตาม scope. ไม่ต้องกรอก IP กล้องซ้ำ/เปิด Terminal. `ft_connect check` ยังคง offline-only; OS route observation ไม่ใช่ camera TCP/login PASS

คุณ Eak ไม่ต้องเปิด Terminal หรือรันคำสั่งด้านล่างเอง. Codex รับผิดชอบงานบน Mac ตามสิทธิ์ที่อนุมัติ; ขั้นตอน CLI ด้านล่างเก็บไว้สำหรับผู้ปฏิบัติงานบน Mac และกรณี Owner สะดวกใช้คอมพิวเตอร์เองเท่านั้น.

OD-27/28: Owner แจ้งเปิด iCloud Drive แล้วและทำขั้นตอนส่ง IP จาก iPhone เสร็จ. PO พบหนึ่งโฟลเดอร์ว่างที่ส่งใน `FootTrafficSetup` บน Mac และบันทึก private IPv4 ลง ignored local config mode 0600 แล้ว; config validation PASS. ไม่ต้องส่ง IP ซ้ำ. `check` ยัง BLOCKED: route/auth/download NOT_TESTED. บัญชี/รหัสผ่านยังไม่ได้รับ; ไม่อ่านไฟล์ส่วนตัวเดิม ไม่เปิด sync/account เพิ่มและไม่อ้างว่า Codex อ่าน Tapo บน iPhone ได้เอง.

อ้างอิงความสามารถ sync ของ iCloud Drive: [Apple Support](https://support.apple.com/en-la/118443) ระบุการใช้ Apple Account เดียวกันและเปิด iCloud Drive บนอุปกรณ์. OD-28 ยืนยันการมาถึงของรายการที่ Owner ส่งครั้งนี้เท่านั้น ไม่ให้สิทธิ์อ่าน iCloud ทั้งหมดหรือรับรอง sync ในอนาคต.

## ส่งเฉพาะ IP ภายในจาก iPhone (ไม่ต้องใช้ Terminal)

1. ในแอป **ไฟล์ (Files)** แตะ **เลือกดู (Browse) → iCloud Drive → FootTrafficSetup**.
2. ต้องเห็น `MAC-READY.txt` ที่ PO สร้างจาก Mac ก่อน. ถ้าไม่เห็น ให้แจ้งเฉพาะว่าไม่พบ folder/marker; ไม่ต้องเปลี่ยน account หรือส่งไฟล์ส่วนตัวอื่น.
3. ดู **IP Address** ใน Tapo ตามขั้นตอนด้านล่าง แล้วกลับมายัง `FootTrafficSetup`.
4. แตะ **… → โฟลเดอร์ใหม่ (New Folder)** ตั้งชื่อโฟลเดอร์เป็นค่า IPv4 ภายในนั้นตรง ๆ และปล่อยโฟลเดอร์ว่าง. ให้มีโฟลเดอร์ IP เพียงหนึ่งรายการเพื่อไม่ให้เลือกเป้าหมายกำกวม. วิธีนี้ใช้เฉพาะ IP ภายใน ไม่ใช้กับ password/account/public IP หรือวิดีโอ และไม่กด Share/Public Link.
5. แจ้งในแชตเพียง **“ทำแล้ว”**. PO จะตรวจเฉพาะจุดส่งที่กำหนดและบันทึก/ตรวจบน Mac; ไม่แสดงชื่อโฟลเดอร์หรือค่าจริงในแชต/output/Git. ถ้า sync ไม่มา/ค่าไม่ใช่ RFC1918/มีหลายเป้าหมาย ให้หยุดและรายงานสถานะที่ไม่เผยค่า; ไม่เดา IP.

ขั้นตอน New Folder อ้างอิง [Apple Files guide](https://support.apple.com/en-euro/guide/iphone/iphab82e0798/ios). การเห็น marker/รับ IP ไม่ใช่หลักฐานว่า private route ถึงร้าน/auth/SD ผ่าน. บัญชี/รหัสผ่านยังไม่รับด้วยวิธีนี้.

## ก่อนเริ่ม

- Python, pytapo, aiofiles และ ffmpeg/ffprobe ติดตั้งแยกไว้ใน runtime ที่ไม่ขึ้น git แล้ว (OD-24) **แต่ยังไม่พิสูจน์ว่าใช้กับกล้องนี้ได้จริง**
- เครื่องมือนี้กรอกและเก็บเฉพาะ **IPv4 ของกล้องในเครือข่ายภายในร้าน** (เช่น ขึ้นต้น `10.`, `172.16.`–`172.31.`, หรือ `192.168.`) ไม่รับรหัสผ่านหรือบัญชีใด ๆ
- ห้ามพิมพ์หรือวาง IP ของกล้องลงในแชตหรือ GitHub ไม่ว่ากรณีใด

## หา IP ของกล้องจากแอป Tapo

1. เปิดแอป Tapo Home แล้วเลือกกล้อง
2. แตะไอคอนรูปเฟือง (Device Settings)
3. เข้า **Device Info** แล้วดูค่า **IP Address**
4. อ้างอิงขั้นตอนทางการที่ผู้ผลิตเผยแพร่: https://www.tp-link.com/us/support/faq/2616/

ค่านี้ใช้กรอกในเครื่องมือด้านล่างเท่านั้น ไม่ต้องแจ้งทีมหรือใส่ในหลักฐานที่แชร์ได้

## วิธีกรอก IP ในเครื่อง (`configure`)

1. เปิด Terminal ที่โฟลเดอร์โปรเจกต์ (ไม่ใช่ทุก Terminal ใหม่จะเริ่มอยู่ที่โฟลเดอร์นี้ ต้องสั่งให้ไปที่นั่นก่อนเสมอ) ทำได้สองวิธี:
   - ใน Finder คลิกขวา (หรือ Control-คลิก) ที่โฟลเดอร์โปรเจกต์ แล้วเลือก **New Terminal at Folder**
   - หรือเปิด Terminal ตามปกติ แล้วพิมพ์ `cd ` (มีเว้นวรรคต่อท้าย) จากนั้นลากโฟลเดอร์โปรเจกต์จาก Finder มาวางในหน้าต่าง Terminal แล้วกด Enter
2. รันคำสั่ง:

   ```bash
   python3 tools/ft_connect.py configure
   ```

3. เครื่องมือจะถามค่า IP **สองครั้งแบบไม่แสดงตัวอักษรบนจอ (masked)** พิมพ์ค่าเดียวกันทั้งสองครั้งแล้วกด Enter
4. ต้องรันจาก Terminal จริง (ไม่ใช่สคริปต์ที่ไม่มีหน้าจอโต้ตอบ) และต้องไม่คัดลอก/วาง IP ไปที่อื่น เช่น ห้ามวางในแชตกับทีมหรือใน prompt ของ AI
5. ถ้าพิมพ์ไม่ตรงกันทั้งสองครั้ง หรือค่าที่พิมพ์ไม่ใช่ IPv4 ภายในร้าน (private/RFC1918) ตามข้อกำหนดด้านบน เครื่องมือจะปฏิเสธและไม่บันทึกอะไร
6. เมื่อสำเร็จ ผล JSON จะแสดง `status: CONFIGURED` และ exit 0 หมายถึงบันทึกในเครื่องแล้ว ค่าถูกเก็บใน ignored `config.local.connection.json` mode 0600; route/auth/download ยัง `NOT_TESTED` ไม่ใช่เชื่อมกล้องสำเร็จ

### ถ้ากดยกเลิกหรือเชื่อมเทอร์มินัลหลุด

ระหว่างขั้นตอนกรอกค่า (ก่อนกด Enter ครบทั้งสองครั้ง) กด Ctrl-C หรือปิดหน้าต่างได้ตลอด เครื่องมือจะเลิกทำงานโดยไม่บันทึกค่าใหม่ใด ๆ ไว้ และถ้ามีไฟล์ค่าที่บันทึกไว้แล้วจากก่อนหน้านี้ ไฟล์นั้นจะยังอยู่เหมือนเดิม ไม่ถูกแก้ไขหรือลบ

## วิธีตรวจสถานะ (`check`)

```bash
python3 tools/ft_connect.py check
```

คำสั่งนี้ตรวจเฉพาะว่าไฟล์ในเครื่อง**มีรูปแบบถูกต้องหรือไม่** (ไม่เปิดเครือข่าย ไม่เชื่อมกล้อง ไม่ import ไลบรารีกล้องใด ๆ) ผลลัพธ์ที่คาดไว้ตอนนี้คือ **BLOCKED** เสมอ เพราะ:

- แม้ไฟล์ค่าจะถูกต้อง ก็ยังไม่เคยพิสูจน์เส้นทางเครือข่ายจากบ้านไปร้านจริง (route = `NOT_TESTED`)
- ไม่มีการตรวจสิทธิ์ยืนยันตัวตนกับกล้อง (auth = `NOT_TESTED`)
- ไม่มีการดาวน์โหลดใด ๆ (download = `NOT_TESTED`, camera_requests = 0)

**`check` ไม่เคยรายงานว่าเชื่อมต่อกล้องสำเร็จ (PASS)** การที่ไฟล์ค่าถูกต้องไม่ใช่หลักฐานว่ากล้องเข้าถึงได้

## เรื่องเส้นทางเครือข่ายที่ยังไม่พิสูจน์ — อธิบายแบบตรงไปตรงมา

- การกรอก IP ในเครื่องมือนี้ **ไม่ได้เปิดทางเชื่อมจากบ้านไปร้าน** มันแค่บันทึกตัวเลขไว้ใช้ในขั้นตอนต่อไป เจ้าของโปรเจกต์อนุมัติให้ลองเชื่อมต่อจากบ้านแล้ว (home trial) และบันทึก endpoint แล้ว OD-28; ยังขาดเส้นทางเครือข่ายส่วนตัวจากบ้านไปร้านที่พิสูจน์แล้ว ไม่ใช่ว่าขาดการอนุมัติในภาพรวม
- ถ้าต้องการให้ Mac ที่บ้านเข้าถึงกล้องที่ร้านได้จริง โดยทั่วไปต้องมี **เส้นทางเครือข่ายส่วนตัวที่ปลอดภัยเข้าไปถึงเครือข่ายร้าน** (เช่น VPN ที่เราเตอร์ของร้านเปิดให้เข้าได้) ไม่ใช่แค่ติดตั้งอะไรที่บ้านฝั่งเดียว
- การเปิดสวิตช์ **Third-Party Compatibility** ในแอป Tapo (ยืนยันแล้วว่าเปิดอยู่) เป็นการอนุญาตให้ "ซอฟต์แวร์ภายนอกคุยกับกล้องได้ในหลักการ" **ไม่ได้สร้างเส้นทางเครือข่ายข้ามจากร้านไปบ้านให้เอง** ต้องมีเส้นทางเครือข่ายที่ใช้งานได้ควบคู่กันเสมอ
- ความสามารถของเราเตอร์ร้าน (ZTE F6107A) ในการเปิด **VPN Server** ให้เข้าได้จากภายนอก ยังเป็น **UNKNOWN** — ยังไม่มีหลักฐานว่าเมนูนี้มีหรือเปิดใช้ได้
- ร้านไม่มีคอมพิวเตอร์หรือ NAS ที่จะใช้เป็นตัวกลาง (gateway) ได้ (ยืนยันแล้ว ไม่ต้องตรวจซ้ำ)
- เอกสารนี้ **ไม่มีขั้นตอนเปิด port forwarding, ตั้ง DMZ หรือติดตั้ง VPN ใด ๆ** และไม่สมมติว่ามีเส้นทางเชื่อมต่อให้ เพราะยังไม่มีหลักฐานยืนยัน

## ถ้าต้องการแก้ไขค่า IP ที่บันทึกไว้แล้ว

เครื่องมือนี้ถูกออกแบบให้ **ไม่เขียนทับไฟล์ค่าที่มีอยู่แล้ว** โดยตั้งใจ (ป้องกันการเผลอเปลี่ยนค่าที่อาจยังใช้งานอยู่) ถ้าต้องการเปลี่ยนค่า:

1. **หยุดก่อน** อย่าลบหรือแก้ไฟล์เอง
2. แจ้ง PO เพื่อจัดขั้นตอนแทนที่ค่าในเครื่องแบบที่ตรวจสอบและควบคุมได้
3. ไม่มีคำสั่ง `--force` หรือทางลัดให้เขียนทับในเครื่องมือนี้ และจะไม่เพิ่มในอนาคตโดยไม่มีคำสั่งเฉพาะ

## สิ่งที่เครื่องมือนี้ไม่ทำ

- ไม่เชื่อมต่อเครือข่ายหรือกล้องจริง ไม่ import ไลบรารีกล้อง (`pytapo`) และไม่มีการยืนยันตัวตนใด ๆ
- ไม่รับหรือเก็บรหัสผ่าน บัญชี หรือข้อมูลอื่นนอกจาก IPv4 ภายในร้าน
- ไม่พิสูจน์ว่าเส้นทางเครือข่ายจากบ้านไปร้านใช้งานได้ ไม่พิสูจน์ auth และไม่ดาวน์โหลดคลิปใด ๆ
