# Bounded SD metadata/listing probe (OD-43)

`tools.ft_sd_probe.run(target_name_sha256, date="20261012")` uses the existing native private cloud login, optional email MFA and unique owner-name digest selection. PO invokes it using the ignored target config. No credentials, tokens, device identifiers or raw replies are stored. Claude only runs synthetic tests. The ordinary cloud CLI remains an auth/inventory diagnostic.

After selection, at most four POST requests go to the pinned APS1 discovery host, to the selected device's validated services-sync path. Templates are checked before transport: metadata (device model/timezone/SD), optional capability, calendar/user ID, and the first clip-list page only. Date is hard-bound to 20261012; channel0 is a listing index, not a proven Fixed Lens ID; indices0–19 cap the page at20 entries. No setters, recovery, retries, redirects, media/relay allocation, downloads, or settings changes. One device budget is90s cooperative, socket timeout at most10s, body limit1MiB each. DNS/blocking system calls are not a hard wall-clock guarantee.

Schema readers require explicit per-method success, one bounded opaque row label per calendar/clip entry, validated camera-local timezone and timestamps within that day. Device and inventory model spelling may differ if both are in the C545D family. Missing schema stays UNKNOWN or BLOCKED. Output contains only enums, bounded counts, booleans, fixed diagnostic stages and normalized timezone offset. Failure stage identifies METADATA/CAPABILITY/CALENDAR/CLIPS; input errors preserve the existing cloud stage. SUCCESS means the bounded diagnostic completed, not full-day completeness, media delivery, Fixed verification or production readiness.

MIT attribution is in THIRD_PARTY_NOTICES.

This describes exported media, not the services-sync channel numbering. Verify actual retrieved media before counting; this probe always reports fixed_mapping UNKNOWN.

Validation: `python3 -m unittest discover -s tests -t . -v`. Synthetic tests substitute network and private dialogs. No upstream camera integration tests. Final PO results and actual trial are recorded in STATUS; developer timed out before final tests, so final validation is NOT_RUN_BY_DEVELOPER.

OD-43 transport correction: unlike inventory GET, device POST must declare `Content-Type: application/json; charset=UTF-8`, matching the pinned upstream cloud headers. Failure reports include only a bounded numeric HTTP status and fixed gateway classification (MODEL_SCHEMA_CHECK_FAILED, HTTP_REDIRECT or UNCLASSIFIED), never the raw body/message. Tests check the actual sent header and redaction. PO full505/505 PASS (85.316s), targeted175/175 PASS (1.912s). Actual outcomes are in STATUS.

Actual C545D trials verified device metadata, timezone+07:00, SD NORMAL and a valid user ID. Calendar responses include dates outside the requested day; the parser validates all returned dates, then selects the exact requested date locally. Only a count of other dates is reported. If the requested date is absent in a nonempty calendar, report NO_MATCHING_DATE and send no clip query. Request scope stays the same single day. Opaque labels are never output or used as request parameters; duplicate and value validation remain enforced.
