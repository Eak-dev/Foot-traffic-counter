# Bounded SD metadata/listing probe (OD-43)

`tools.ft_sd_probe.run(target_name_sha256, date="20261012")` uses the existing native private cloud login, optional email MFA and unique owner-name digest selection. PO invokes it using the ignored target config. No credentials, tokens, device identifiers or raw replies are stored. Claude only runs synthetic tests. The ordinary cloud CLI remains an auth/inventory diagnostic.

After selection, at most four POST requests go to the pinned APS1 discovery host, to the selected device's validated services-sync path. Templates are checked before transport: metadata (device model/timezone/SD), optional capability, calendar/user ID, and the first clip-list page only. Date is hard-bound to 20261012; channel0 is a listing index, not a proven Fixed Lens ID; indices0–19 cap the page at20 entries. No setters, recovery, retries, redirects, media/relay allocation, downloads, or settings changes. One device budget is90s cooperative, socket timeout at most10s, body limit1MiB each. DNS/blocking system calls are not a hard wall-clock guarantee.

Schema readers require explicit per-method success, canonical numeric keys for calendar/clip rows, validated camera-local timezone and timestamps within that day. Device and inventory model spelling may differ if both are in the C545D family. Missing schema stays UNKNOWN or BLOCKED. Output contains only enums, bounded counts, booleans, fixed diagnostic stages and normalized timezone offset. Failure stage identifies METADATA/CAPABILITY/CALENDAR/CLIPS; input errors preserve the existing cloud stage. SUCCESS means the bounded diagnostic completed, not full-day completeness, media delivery, Fixed verification or production readiness.
